# Расписание 8Г: GitHub Pages + отдельный API

Это выделенная копия сайта. Исходные файлы в корне сохранены для отката и старого Render; остальные проекты сюда не включены.

## Локальный запуск

Python 3.10+ (проверено на 3.12):

```text
py -m pip install -r requirements.txt
py app.py
```

Без pywebpush сайт работает, но отправка push недоступна.
Данные сохраняются в `data/` (или `DATA_DIR`), папка исключена из Git.
Не переносите ключи и подписки в публичные файлы. Историю `days_store.json` при переносе сервера скопируйте в DATA_DIR отдельно, не через Git.

## Работа без интернета

Сайт полностью работоспособен офлайн, в том числе при самом первом запуске:

* `offline-data.js` — встроенная копия расписания. Подключается обычным `<script>`,
  поэтому доступна даже при открытии `index.html` двойным щелчком (`file://`).
* Шрифт Manrope лежит в `assets/fonts/`, внешние запросы к Google Fonts убраны.
* `sw.js` (v26) кэширует статику cache-first и сохраняет последний ответ
  `/api/schedule`; при отсутствии сети расписание берётся из кэша без ожидания таймаута.
* При `navigator.onLine === false` сетевой запрос не делается вовсе — страница
  рисует сохранённые данные мгновенно и показывает спокойный статус «Офлайн».
* Успешная загрузка с API сохраняется в `localStorage` (`sch.data`), так что
  офлайн-копия сама свежеет при каждом визите с интернетом.

Обновить встроенную копию вручную (в корне и во всех `*-dist`):

```text
py refresh_snapshot.py
py refresh_snapshot.py --api http://127.0.0.1:8000/api/schedule
```

Без сети скрипт возьмёт дни из `data/days_store.json`. Открытый как файл сайт
не обращается к API (у `file://` нет CORS): чтобы подтянуть свежую таблицу,
запустите `py app.py` и откройте `http://127.0.0.1:8000` с интернетом либо
выполните `refresh_snapshot.py` на машине с сетью.

На `localhost`, в локальной сети и в `file://` сайт игнорирует адрес из
`config.js` и работает со своим сервером / встроенной копией; внешний API
используется только на GitHub Pages.

## API вне Render

GitHub Pages не запускает Python. Нужен отдельный HTTPS-сервер с постоянным диском.
Рабочее зеркало API: https://nassda.pythonanywhere.com (проверено 2026-11-04: `/healthz` → ok, `/api/schedule` → ok:true, CORS для github.io включён).
Старый адрес schedule8g.pythonanywhere.com возвращал заглушку 404: это НЕ рабочее зеркало.
На PythonAnywhere настройте веб-приложение WSGI, виртуальное окружение с requirements.txt и путь к этой папке. Пример WSGI:

```python
import os
import sys
sys.path.insert(0, '/home/USERNAME/school-schedule/school-schedule')
os.environ['DATA_DIR'] = '/home/USERNAME/schedule-private'
os.environ['SELF_URL'] = 'https://USERNAME.pythonanywhere.com'
os.environ['ALLOWED_ORIGINS'] = 'https://nikita2272282299.github.io'
from pa_wsgi import application
```

Проверить `/healthz`, `/api/diag`, `/api/schedule?force=1`, доступ к Google-таблице и Web Push. Доступность домена из РФ не гарантируется: проверить без VPN с целевых устройств.
Бесплатный WSGI-хостинг не обеспечивает постоянный фоновый watcher: для уведомлений без посетителей нужен разрешённый планировщик/постоянный процесс. Проверить ограничения тарифа перед выбором. Текущий watcher работает при запуске `app.py`, но не при WSGI.

## Подключение Pages

В `config.js` для Pages указан реальный адрес API `https://nassda.pythonanywhere.com` (без `/api`). Не указывать выдуманный или неработающий адрес. Пустая строка предназначена для совместного локального размещения.
Сервер API должен использовать `pa_wsgi.application` с ограниченным CORS.
В репозитории `Nikita2272282299/school-schedule`: Settings → Pages → Source → GitHub Actions.
Workflow `.github/workflows/schedule-pages.yml` проверяет код, собирает только разрешённые публичные файлы из `build_pages.py` (сейчас 11, включая офлайн-копию и локальные шрифты) и развёртывает Pages.
Ожидаемый адрес: https://nikita2272282299.github.io/school-schedule/

```text
py -m unittest discover -s school-schedule/tests
py school-schedule/build_pages.py
```

Команды выше запускаются из корня репозитория. `pages-dist/` — автоматически создаваемый артефакт, не исходники.
После публикации проверить день/неделю, обновление, темы, ссылку «Поделиться», офлайн после первого посещения, установку на телефон и уведомление с переходом на конкретный день. Старые подписки привязаны к домену Render: на Pages потребуется включить уведомления заново.
Render не отключать, пока сайт и API не проверены без VPN.

## Версия 267: скорость, настройки, плавность

* **Первый экран без ожидания сети.** `offline-data.js` и `config.js` подгружаются
  через `<link rel="preload">`, сетевое обновление запускается после первого кадра,
  а Service Worker (v27) отдаёт HTML и конфиги сразу из кэша, подтягивая свежую
  версию в фоне. Фоновая загрузка больше не перестраивает DOM, если данные не
  изменились (`dataSig()`).
* **Настройки не теряются.** `sch.prefs` пишется в `localStorage` и дублируется в
  cookie; при старте читается первое доступное хранилище, значения проходят
  валидацию и миграцию (`sanitizePrefs`). Кнопка «Сбросить сохранённые данные»
  переименована в «Обновить расписание с сервера» и настройки не трогает.
* **Перенос между адресами.** Разные домены не шарят `localStorage`, поэтому в
  настройках есть «Скопировать мои настройки»: ссылка с параметром `?s=` переносит
  тему и переключатели на другой адрес или устройство, после применения параметр
  убирается из адресной строки.
* **Плавность.** Общий ритм переходов для всех кнопок, мягкие `:active`/hover,
  «пружинящий» переключатель, кросс-фейд при смене темы (`theme-fade`), мягкое
  появление содержимого при смене дня, более крупные области нажатия и аккуратный
  статусный чип в узкой боковой колонке. Всё уважает `prefers-reduced-motion`.

Обновление «основы» на PythonAnywhere: `pa_update.sh` в корне репозитория
(одна команда в Bash-консоли, подробности в `README-PYTHONANYWHERE.md`).
