# Исправленная версия расписания

## Что изменено

- HTML-разбор Google Sheets с учётом реальных colspan/rowspan: объединённая ячейка попадает во все классы, которые она действительно охватывает. По соседним ячейкам CSV уроки не угадываются.
- Пустые строки не обрывают чтение дня; повторные блоки одного класса дополняют друг друга. Это исправлено в сайте, Python API и Android-парсере.
- Записи `англ319/308(1)`, `Англ210а`, `Физика (305(2),407)` распознаются как кабинеты. `(пр)` не превращается в кабинет.
- Сайт повторно проверяет связь с Android-приложением при загрузке и возврате. Не используется ложный флаг «APK установлен»: браузер не может надёжно узнать, установлен ли отдельный APK.
- Для поддерживаемого браузера/установленного PWA восстановлены Service Worker и Web Push: включение, тест, выключение, восстановление подписки, сообщения об ошибках сервера. Напоминания за 5 минут остаются функцией APK. Сервер Web Push в этом проекте обслуживает только класс 8Г — интерфейс предупреждает об этом для других классов.
- В Android добавлены переход к разрешению точных напоминаний, восстановление после смены времени/перезапуска, защита от повторного напоминания. Время школы — Asia/Yekaterinburg. При задержке уведомление не пишет ошибочное «через 5 минут».
- Ошибка загрузки второстепенного ресурса WebView больше не переключает всё приложение на офлайн-копию.
- Название сайта, PWA и APK — «Расписание». Идентификатор пакета Android сохранён для обновления поверх прежнего APK.
- Нейтральная иконка календаря без «8Г», включая адаптивные Android-иконки. Образец пользователя в чате отсутствовал; это самостоятел��ный вариант, не копия образца.
- У темы «Новый год» убрана только метка NEW, тема сохранена.
- Шрифты входят в офлайн-копию. Дистрибутивы синхронизированы.

## Как опубликовать

1. Распакуйте ZIP и перенесите **содержимое** папки `school-schedule-main` в существующий репозиторий с заменой файлов. Не создавайте лишнюю вложенную папку и не загружайте ZIP вместо файлов. Основной исходник сайта — `school-schedule/index.html`; папка `.github/workflows` тоже нужна.
2. Сохраните изменения в ветку `main`. Дождитесь зелёного `Schedule GitHub Pages` во вкладке Actions. Обновление снимка теперь запускается и при обычной публикации. Если Actions сообщает об ошибке production API, проверьте сервер, его HTTPS и CORS.
3. **Обновите PythonAnywhere/API отдельно** по существующей инструкции README-PYTHONANYWHERE.md и перезагрузите веб-приложение. Одной публикации GitHub Pages недостаточно для обновления Python-сервера.
4. Дождитесь сборки `Android APK` в Actions; скачайте `raspisanie-8g.apk` из релиза `app` и установите поверх старого приложения. Старое имя файла сохранено, чтобы не ломать ссылку загрузки. Ключ подписи в проекте сохранён.
5. На телефоне откройте настройки уведомлений, разрешите уведомления Android, при необходимости — точные напоминания. Нажмите «Проверить». Если производитель ограничивает фон, разрешите фоновую работу приложения в настройках батареи.
6. Для PWA откройте настройки → Уведомления → Включить → Тест. На iPhone требуется установленное на домашний экран PWA и iOS 16.4+. При открытии в обычной вкладке это не тот же контейнер хранения, что установленное PWA.

## Важные ограничения и проверка

- Автотесты: 12 Python-тестов, проверка синтаксиса JavaScript, регрессии JS-парсера/обработчика push. Дополнительно выполнены браузерные проверки кабинетов, объединённых ячеек, повторных блоков, позднего Android bridge и офлайн-перезагрузки PWA. Проверены мобильный экран 390px, настройки 1280px и новая иконка.
- Сборка публичных файлов `build_pages.py` проходит. Команды из корня: `python -m unittest discover -s school-schedule/tests`, `node school-schedule/check_js.cjs`, `node school-schedule/check_fixes.cjs`, `python school-schedule/build_pages.py`.
- APK **не собран и не проверен на физическом Android**: в рабочей среде нет Android SDK/компилятора Java. Изменения Android требуют сборки GitHub Actions и проверки на телефоне. Новые разрешения и интерфейс не появятся в уже установленном старом APK без его обновления.
- Доставка системных уведомлений через настоящий push-сервис не проверена: нет доступа к живому серверу и телефону. Регистрация Service Worker, офлайн-загрузка и обработчики push проверены локально.
- На бесплатном PythonAnywhere WSGI не гарантирует постоянную фоновую проверку. Для Web Push при закрытом сайте нужен разрешённый хостингом фоновый процесс/планировщик с постоянными VAPID-ключами и подписками. Браузерный Service Worker сам по расписанию таблицу не опрашивает. Android использует собственные фоновые задания; ОС может задерживать их, особенно при энергосбережении или принудительной остановке приложения.
- Живая Google-таблица из среды недоступна, поэтому наличие конкретного урока «хим пр» за сегодня не подтверждено. Обработка объединённых уроков проверена на синтетических таблицах. Встроенное расписание не подменялось выдуманными уроками: после публикации нужно получить свежую таблицу.
- Если HTML-версия таблицы недоступна, используется CSV; в CSV нет сведений об объединении ячеек. Для правильного отображения таких уроков требуется доступная HTML-версия либо обновлённый API/снимок, полученный из неё.
- Нельзя гарантировать отсутствие всех возможных багов; перечислены проверенные сценарии и оставшиеся ограничения.
